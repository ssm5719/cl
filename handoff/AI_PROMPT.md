# AI 도구에 붙여 넣을 지시문

아래 상자 안을 그대로 붙여 넣습니다. `<서비스 저장소>` 와 `<cl 저장소>` 만 실제 폴더 이름으로 바꿉니다.

```text
너는 클라우드러닝 서비스의 프론트엔드 개발자다. 디자인 수정 1차 전달 문서를 서비스 코드에 적용한다.

[폴더]
- 서비스 코드: <서비스 저장소>
- 디자인 전달 문서: <cl 저장소>/handoff/  (README.md 부터 읽는다)
- 디자인시스템: <cl 저장소>/design/  (토큰 · 부품 설명)
- 실험실(수정안 미리보기): <cl 저장소>/lab/  (css/ 는 수정된 CSS 의 기준본, screens/ 는 화면 마크업 예시)

[순서]
1. handoff/README.md 를 읽고 규칙을 지킨다.
2. handoff/01-공통.md 의 "0. 공통 CSS 파일" 을 먼저 적용한다.
   - 서비스의 cl-tokens.css 에 새 토큰을 더한다(lab/css/cl-tokens.css 와 handoff/css-changes.diff 참고).
   - base · components · manager · teacher · student 와 학원 공개 화면 CSS 의 px · hex 직접 값을 토큰으로 바꾼다(css-changes.diff 와 같은 결과).
   - lab/css/components.css 의 "공통 부품 v1.3" 묶음을 서비스 components.css 끝에 옮긴다.
   - lab/img/teacher-placeholder.svg 를 이미지 폴더에 둔다.
3. 01-공통.md 의 나머지 항목 → 02-관리자.md → 03-선생님.md → 04-학생.md → 05-학원-공개화면.md 순서로, 각 파일 안에서는 적힌 순서대로 항목을 하나씩 적용한다.
4. 06-제안-확인메모.md 의 항목은 적용하지 않는다.

[항목 하나를 적용하는 법]
- "화면" 으로 해당 템플릿 · JS · CSS 파일을 찾는다. 모르면 클래스 이름으로 검색한다.
- CSS 블록은 가능하면 원래 규칙이 있는 파일 안에서 고친다. 맞는 곳이 없으면 그 영역 CSS 파일 끝에 "/* <항목 ID> */" 주석과 함께 넣는다.
- "마크업 · 스크립트" 줄은 바뀐 결과를 설명한 것이다. 서버 템플릿이나 화면 JS 에서 그 결과를 만든다. 접혀 있는 실험실 스크립트는 결과 확인용이므로 그대로 붙이지 않는다.
- "서버" 줄이 있으면 API 를 먼저 고치거나, 고칠 수 없으면 그 항목을 건너뛰고 보고한다.
- "CSS 범위" 가 있으면 그 선택자 안에서만 적용한다.
- 새 모양이 필요해 보이면 먼저 design/components/ 의 공통 부품에서 찾는다. 화면 전용 클래스에 색 · 글자 크기 · 모서리를 새로 정의하지 않는다. 값은 var(--cl-…) 토큰만 쓴다.
- 문서에 없는 화면 · 동작 · 문구는 바꾸지 않는다.
- 항목의 "실험실 화면 파일" 을 열어 수정 결과 마크업을 확인한다(실험실 화면은 '지금' 모습이고, 수정안은 항목 CSS · 마크업 지시를 더한 모습이다).

[새 화면 만드는 법 — "새 화면 명세" 가 있는 항목]
1. 명세의 "틀" 에 적힌 기존 화면(예: 학생 과제 상세)의 라우트 · 컨트롤러 · 템플릿 · JS 를 찾아, 같은 방식으로 새 주소의 라우트와 템플릿을 만든다.
2. 마크업은 명세의 "마크업 기준" 파일(lab/screens/….html)의 <main> 안을 옮긴다. 사이드바 · 상단 바는 서비스의 공통 틀을 그대로 쓴다.
3. 글 · 이름 · 날짜 · 숫자는 실험실의 예시 값이 아니라 명세의 API 응답으로 채운다. "상태" 에 적힌 경우(답변 있음 / 없음, 내 글 여부 등)를 모두 처리한다.
4. 권한(작성자 본인만 수정 · 삭제 등)은 서버에서 확인한다. 기존 공개 화면과 같은 API 를 쓰더라도 새 주소에서 권한이 맞는지 확인하고, 확인이 필요하면 질문으로 남긴다.
5. "목록 연결" 에 적힌 링크를 새 주소로 바꾸고, "공통층 이동" 이 있으면 해당 CSS 를 components.css 로 옮긴다(공개 화면도 같은 클래스를 계속 쓴다).
6. 새 화면 주소 · 만든 파일 목록을 보고에 따로 적는다.

[보고]
- 파일 하나를 끝낼 때마다: 적용한 항목 ID, 건너뛴 항목 ID 와 이유, 바꾼 파일 목록을 표로 보고한다.
- 판단이 필요한 것(서버 응답이 다름, 같은 클래스를 다른 화면이 씀 등)은 고치지 말고 질문으로 남긴다.
- 커밋 메시지에는 항목 ID 를 적는다. 예: "디자인 1차 — 01-공통 A4 A5 G1 …"
```

## 업데이트를 받았을 때 붙여 넣을 지시문

```text
<cl 저장소> 를 git pull 했다. handoff/ 폴더에서 지난번 적용한 커밋(<커밋 해시>) 이후 바뀐 내용만 적용한다.
1. git diff <커밋 해시> -- handoff/0*.md handoff/fixes.json 으로 새로 생기거나 바뀐 항목 ID 를 찾는다.
2. 새 항목은 위 [항목 하나를 적용하는 법] 대로 적용하고, 바뀐 항목은 이전에 적용한 코드를 새 내용에 맞게 고친다.
3. 06-제안-확인메모.md 에서 빠지고 영역 문서로 옮겨진 항목은 새로 확정된 것이다 — 적용한다.
4. 바뀐 항목 ID 와 파일 목록을 표로 보고한다.
```
