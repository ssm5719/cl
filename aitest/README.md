# AI 출제 수준 테스트

시험 출제 기능의 화면을 다시 그리기 전에 **"AI가 실제로 쓸 만한 문항을 뽑는가"를 데이터로 확인**하는 도구입니다.
실제 시험지를 Claude API에 넣어 문항을 만들고, 선생님이 검토 화면에서 하나씩 판정한 결과를 보고서로 묶습니다.

| 재는 것 | 어디서 | 기획에서 정해지는 것 |
|---|---|---|
| ① 시험지를 통째로 넣었을 때 지문 · 문항을 맞게 나누는 비율 | `split` → 검토 화면 ① | "통째로 넣기"를 기본으로 할지, 나누기 확인 화면이 필요한지 |
| ② 손대지 않고 그대로 쓸 수 있는 문항 비율 (고쳐서 쓸 수 있는 비율) | `generate` → 검토 화면 ② | 일괄 생성 / 지문 골라 돌리기 / 보류 |
| ③ 문항 하나 검토에 드는 시간 | 검토 화면 ② 타이머 | 검토 화면을 얼마나 공들여 만들지, 실제로 시간이 줄어드는지 |
| ④ 자동 검사(정답 숨기고 다시 풀기 · 근거 문장 대조)가 나쁜 문항을 걸러 내는지 | `verify` | 걸린 문항을 미리 빼거나 표시할지 |
| ⑤ 비용 · 대기 시간 | `calls.jsonl` | 한도 · 요금, 진행 표시가 필요한지 |

## 1. 테스트 구성 (측정표)

한 번에 선생님 한 분이 1시간 안팎으로 검토할 수 있는 양으로 잡았습니다. 시험지 나누기는 항상 **시험지 전체**로 하고, 문항 만들기만 일부 단위로 합니다.

| # | 과목 | 넣을 자료 | 문항 만들 단위 | 출제 방식 | 문항 수 | 검토 |
|---|---|---|---|---|---|---|
| 1 | 영어 · 모의 | 평가원 모의평가 영어 1회 (PDF) | 18~40번 중 10지문 (목적 · 요지 · 제목 · 빈칸 2 · 순서 · 삽입 · 요약 · 어법 · 어휘) | `same_type` × 2 | 20 | 영어 선생님 1~2명 |
| 2 | 영어 · 내신 | 교과서 또는 부교재 지문 5개 (.txt 또는 PDF) | 전체 | `set3` | 15 | 같은 선생님 |
| 3 | 국어 | 교육청 학력평가 국어 1회 (PDF) | 독서 2묶음 + 문학 2묶음 | `same_type` × 3 | 12 | 국어 선생님 1명 |
| 4 | 수학 | 교육청 학력평가 수학 1회 (PDF) | 그림 없는 문항 10개 (2 · 3점 6, 4점 4) | `twin` × 1 | 10 | 수학 선생님 1명 |
| 5 | (선택) 스캔본 | 학교 시험지 사진 · 스캔 PDF 1부 | 나누기만 | — | — | 위 선생님 중 1명 |

- 영어 선생님이 두 분이면 1번을 두 분 모두 검토해 주세요. 보고서가 두 기록을 합칩니다.
- 그림 · 도표가 있는 단위는 기본으로 문항 만들기에서 뺍니다. 이것도 결과입니다(자동으로 못 다루는 비율). 넣어 보려면 `--include-figures`.
- 시험지 PDF는 `inputs/` 에 두세요. **이 폴더와 `outputs/` 는 저장소에 올라가지 않습니다**(`.gitignore`). 기출 · 교재는 저작권이 있으니 내부 테스트로만 쓰고 공유 폴더에 올리지 마세요.

## 2. 설치

Python 3.10 이상.

```bash
cd aitest
```

```bash
python -m venv .venv && source .venv/bin/activate
```

```bash
pip install -r requirements.txt
```

API 키는 [Claude Console](https://platform.claude.com/)에서 만들어 환경 변수로 둡니다.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

먼저 API 없이 흐름만 확인해 볼 수 있습니다. `outputs/demo/review.html` 이 생깁니다.

```bash
python aitest.py all --mock --name demo
```

## 3. 실행 순서 (영어 예)

**① 시험지 나누기** — 시험지 전체를 넣습니다.

```bash
python aitest.py split --name eng-0926 --subject 영어 inputs/2026-09-모의평가-영어.pdf
```

**② 문항 만들기** — 만들 단위의 첫 문항 번호를 고릅니다. 국어 묶음은 `16-19` 처럼 묶음의 첫 번호를 적습니다.

```bash
python aitest.py generate --name eng-0926 --units 18,20,22,24,29,30,31,33,36,38 --per-unit 2
```

**③ 자동 검사**

```bash
python aitest.py verify --name eng-0926
```

**④ 검토 화면 만들기** — `outputs/eng-0926/review.html` 하나가 생깁니다. 이 파일만 선생님께 보내면 됩니다(인터넷 없이 열림).

```bash
python aitest.py review --name eng-0926
```

①~④를 한 번에 돌릴 수도 있습니다.

```bash
python aitest.py all --name eng-0926 --subject 영어 inputs/2026-09-모의평가-영어.pdf --units 18,20,22,24,29,30,31,33,36,38
```

**⑤ 보고서** — 선생님이 돌려준 JSON 들을 넣습니다. `outputs/eng-0926/report.md` 와 문항별 `report-items.csv` 가 생깁니다.

```bash
python aitest.py report --name eng-0926 review-eng-0926-김지수.json review-eng-0926-이현우.json
```

다른 과목 예:

```bash
python aitest.py all --name kor-0604 --subject 국어 inputs/2025-06-고2-국어.pdf --units 1-3,8-11 --per-unit 3
```

```bash
python aitest.py all --name math-0310 --subject 수학 inputs/2025-03-고1-수학.pdf --units 1-6,15-18 --per-unit 1
```

```bash
python aitest.py all --name eng-naesin --subject 영어 --preset set3 inputs/교과서-3과.txt inputs/교과서-4과.txt
```

## 4. 선생님께 보낼 안내 (복사해서 쓰세요)

> AI가 만든 문항이 실제로 쓸 만한지 확인하려고 합니다. 첨부한 `review.html` 을 크롬으로 열어 주세요.
> 1. 위쪽에 이름을 적어 주세요.
> 2. **① 지문 나누기 확인**: 원본 시험지를 옆에 띄우고, 지문 경계 · 빠진 문장 · 유형 이름이 맞는지만 봐 주세요.
> 3. **② 문항 검토**: 문항마다 "그대로 사용 / 고쳐서 사용 / 사용 불가"를 골라 주세요(키보드 1 · 2 · 3, 다음은 Enter). 실제 수업에 낸다고 생각하고, 오탈자 한두 개 정도만 고치면 되면 "고쳐서 사용"입니다. 문항마다 검토 시간이 자동으로 재지니, 중간에 다른 일을 하실 때는 창을 내려 두세요(창이 가려지면 멈춥니다).
> 4. **③ 결과 내려받기**: 직접 만들 때 걸리는 시간을 적고 JSON 을 내려받아 보내 주세요.
> 중간에 닫아도 같은 브라우저로 다시 열면 이어서 할 수 있습니다.

자동 검사 결과는 판정을 고른 뒤에만 보입니다. 먼저 보면 판단이 쏠리기 때문입니다.

## 5. 판정 기준

보고서 마지막 '판정'은 아래 기준으로 나옵니다(`aitest.py` 맨 위 상수로 바꿀 수 있습니다).

| 결과 | 기준 | 기획에 반영 |
|---|---|---|
| **A · 일괄 생성 기본** | 그대로 사용 ≥ 80% | 통째로 넣고 한꺼번에 만든 뒤 훑어보는 흐름. 검토 화면은 가볍게 |
| **B · 지문 골라 돌리기 + 검토 화면** | 그대로 + 고쳐서 ≥ 70% | 지문을 골라 묶어 돌리고, 문항별 고치기 · 다시 만들기를 꼭 넣음 |
| **C · 보류** | 그대로 + 고쳐서 < 70% | 지시문을 고쳐 다시 시험하거나, 이 과목 · 방식을 1차 범위에서 뺌 |
| 나누기 확인 화면 필요 | 지문 나누기 맞음 < 90% | 올린 뒤 "나누기 결과 확인" 단계를 둠 |
| 자동 검사 활용 | 통과 문항의 '사용 불가' ≤ 15% 이고 걸린 문항의 '사용 불가' ≥ 50% | 걸린 문항을 미리 빼거나 표시해서 보여 줌 |

과목 · 유형마다 따로 판단하세요. 예를 들어 영어는 A, 수학은 C가 나올 수 있고, 그러면 1차는 영어 · 국어만 여는 것이 맞습니다.

## 6. 비용 · 시간

- 기본 모델은 `claude-opus-5-5`, 문항 만들기 · 검사는 effort `high`, 나누기는 `medium` 입니다.
- 실제 토큰 · 비용은 `outputs/<이름>/calls.jsonl` 에 호출마다 남고 보고서에 합계가 나옵니다. 위 측정표 전체를 돌려도 대략 수십 달러 안쪽으로 예상하지만, 첫 실행 보고서의 실제 값을 기준으로 보세요.
- 수학 자동 검사는 Anthropic 쪽 샌드박스에서 Python(sympy)으로 계산합니다(code_execution, 컨테이너 사용료 별도 · 소액).
- 안전 분류기가 요청을 잘못 거절하는 경우를 대비해 서버 쪽 대체 실행(`fallbacks: "default"`)을 켜 두었습니다. 끄려면 `aitest.py` 의 `FALLBACK_MODELS` 를 비우세요.
- 비용을 비교하려면 같은 시험지를 `--model claude-sonnet-5-5 --name eng-0926-sonnet` 처럼 다른 이름으로 한 번 더 돌려 보세요.

## 7. 파일

| 파일 | 내용 |
|---|---|
| `aitest.py` | 실행 스크립트 (split · generate · verify · review · report · all) |
| `prompts.py` | 지시문 · 출제 방식(프리셋) · JSON 형식. **품질이 낮게 나오면 여기를 고쳐 다시 돌립니다** |
| `review_template.html` | 선생님 검토 화면 틀 |
| `mock/split.json` | `--mock` 용 가짜 시험지(직접 쓴 예문) |
| `sample/review-demo.html` | 가짜 데이터로 만든 검토 화면 견본 |
| `results/` | 실제 시험지로 돌린 테스트 결과 정리 (1차 · 유형 묶음 2차) |
| `docs/` | 시험 출제 프로토타입 설계(`specs/`) · 구현 계획(`plans/`) |
| `prototype/` | 시험 출제 · 시험 보관함 프로토타입 화면 — [`prototype/README.md`](prototype/README.md) |
| `outputs/<이름>/` | 실행 결과: `split.json` · `items.json` · `calls.jsonl` · `review.html` · `report.md` |

지시문을 고쳐 다시 돌릴 때는 `--name` 을 바꾸세요(예: `eng-0926-v2`). 같은 이름에 `generate --force` 로 덮으면 이미 받은 검토 기록과 문항이 맞지 않게 됩니다.
