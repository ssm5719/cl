# 시험 출제 · 시험 보관함 프로토타입 설계

작성 2026-10-28 · 상태: 검토 요청 · 관리 위치 `aitest/`

## 1. 목적과 범위

### 무엇을 위한 것인가
클라우드러닝 학원 홈페이지의 **선생님 관리자 페이지**에 넣을 **시험 출제 / 시험 보관함** 기능을 눌러 볼 수 있게 만든 프로토타입이다. 기획 논의 중 수정이 잦았던 흐름을 한 화면에서 확인하고 고치기 위해 만든다.

- **1차 용도: 내부 기획 확인 · 보고.** 1차 AI 테스트에서 실제로 만든 문항을 넣어 "AI가 이렇게 만든다"를 보여 준다.
- **2차 용도: 선생님 사용성 테스트.** 같은 화면에서 실제 AI 를 불러 문항을 만들 수 있게 한다(9장).
- 개발자 전달용 상세 명세는 이번 범위가 아니다(개발자 회의 후 따로 만든다).

### 지향
- 시험 출제 전문 서비스가 아니라 **선생님 손품을 덜어 주는 기능**이다.
- 다음-다음 흐름은 고집하지 않는다. 클릭이 늘어도 **무엇이 몇 개 나오는지 예측 가능한 화면**을 우선한다.
- 기본 화면은 단순하게, 세밀한 선택은 펼쳐서 한다.

### 범위
| 넣는 것 | 빼는 것 |
|---|---|
| 영어 · 국어 | 수학 (수식 · 그림 · 계산 검증이 필요해 따로 검토) |
| 문제지 · 정답지 인쇄(PDF) | 학생 응시 · 배포 · 채점 |
| 기출 PDF 올리기 → 지문별 보관 | 사용량 한도 · 요금 화면 |
| 지문 붙여넣기 | 그림 · 도표가 필요한 지문의 자동 출제 (보관만 함) |
| 만든 시험지 목록 (다시 인쇄 · 고치기 · 복사) | 학원 간 자료 공유 |

### 성공 기준
- 보고 자리에서 처음 보는 사람이 **기출 시험지 하나로 변형 문제지를 출력하는 흐름**을 설명 없이 따라갈 수 있다.
- 각 화면에서 "다음에 무엇이 몇 개 나오는지"를 화면 글만으로 알 수 있다.
- 1차 테스트에서 나온 이슈(원래 정답 노출 · 선택지 언어 · 그림 지문)가 화면에서 어떻게 다뤄지는지 보인다.

## 2. 메뉴 구조

선생님 관리자 사이드바에 **'나의 시험'** 묶음을 추가한다(기존 '나의 강좌'와 같은 모양). 상단 '새로 만들기' 메뉴에도 '시험지 만들기'를 넣는다.

```
나의 시험
├─ 시험 출제      만든 시험지 목록 → 새 시험지 만들기(4단계)
└─ 시험 보관함    보관함 목록 → 시험지 올리기 / 시험지 상세
```

- **시험 출제**에는 AI로 만들어 저장한 시험지가 있다.
- **시험 보관함**에는 원래 자료(기출 시험지 · 붙여 넣은 지문)가 있다. 같은 학원 · 같은 과목 선생님끼리 함께 본다.

## 3. 시험 출제 — 만든 시험지 목록

- 표: 제목 · 과목 · 문항 수 · 원래 자료 · 상태(작성 중 / 완성) · 만든 날
- 행 동작: **다시 인쇄** · **이어서 고치기** · **복사해서 새로 만들기** · 삭제
- 위: **[새 시험지 만들기]**, 과목 필터, 검색
- 비어 있을 때: "아직 만든 시험지가 없어요" + [새 시험지 만들기] + [보관함에 시험지 올리기]

## 4. 새 시험지 만들기 (4단계)

공통
- 위: 단계 표시 `① 자료 → ② 방식 → ③ 검토 → ④ 인쇄`. 지난 단계는 눌러서 돌아갈 수 있다.
- 아래 고정 바: 현재 선택 요약(예: "지문 8개 · 16문항") + [이전] [다음].
- 만들던 시험지는 목록에 '작성 중'으로 남는다.

### ① 자료 고르기
- **과목**: 영어 / 국어. 선생님 담당 과목이 기본.
- 탭 **[보관함에서] [지문 붙여넣기]**
- **보관함에서**
  - 왼쪽: 시험지 목록(검색, 학년 · 종류 필터). 오른쪽: 고른 시험지의 지문 목록(번호 · 유형 · 첫 줄).
  - 지문 목록 위: **[전체 선택]**, 유형 필터 칩("빈칸만", "순서 · 삽입만" …).
  - 그림 · 도표가 필요한 지문은 흐리게 두고 고를 수 없다. 이유를 한 줄로 보인다("그림이 있어 자동 출제에서 빠져요").
  - 여러 시험지에서 섞어 고를 수 있다. 아래 바에 "고른 지문 8개"와 지운 지문 되돌리기.
- **지문 붙여넣기**
  - 지문 제목 · 본문 입력, [지문 추가]로 여러 개.
  - "보관함에도 저장" 기본 켬.
  - 자료 사용 권리 확인은 **처음 한 번만** 받는다(선생님 계정 기준).

### ② 만들 방식
기본 화면에서는 **유형 묶음 칩**을 여러 개 고른다. 세밀하게 고르고 싶을 때만 **[세부 유형 펼치기]** 를 쓴다.

```
어떤 문제를 만들까요?  (여러 개 고르면 지문마다 골고루 섞어요)
[원래 유형 그대로]   ← 보관함 기출 지문일 때만 보임

영어  [대의 파악] [세부 내용] [빈칸] [글의 흐름] [요약문] [어법 · 어휘] [서술형]
국어  [사실적 읽기] [추론적 읽기] [<보기> 적용 · 비판] [어휘] [표현 · 감상] [서술형]

형태   (5지 선다)  4지 선다  OX
난이도 (원래 수준)  쉽게  어렵게  섞어서
문항 수  지문당 [1] (2) [3]   →  지문 8개 × 2문항 = 16문항
         총 문항 수에 맞추기 · 지문별로 바꾸기
▸ 자세히 설정
```

**유형 묶음과 세부 유형**

| 과목 | 묶음 | 세부 유형 (펼치면) |
|---|---|---|
| 영어 | 대의 파악 | 주제 · 제목 · 요지 · 주장 · 목적 |
| | 세부 내용 | 내용 일치 · 불일치 · 답할 수 없는 질문 |
| | 빈칸 | 한 단어 · 구/절 |
| | 글의 흐름 | 순서 · 순서(처음 · 끝 고정) · 문장 삽입 · 무관한 문장 |
| | 요약문 | (A)(B) 요약문 |
| | 어법 · 어휘 | 어법 밑줄 · 어법 개수 · 어휘 밑줄 · 어휘 개수 · 의미가 같은 것 · 고난도 내신형 |
| | 서술형 | 요약문 빈칸 쓰기 · 어법 틀린 곳 고치기 · 조건 영작 · 주제문 쓰기 |
| 국어 | 사실적 읽기 | 내용 일치 · 세부 정보 확인 |
| | 추론적 읽기 | 내용 추론 · 견해 비교 · 전제 · 이유 |
| | <보기> 적용 · 비판 | 구체적 사례 적용 · 외적 준거 감상 |
| | 어휘 | 문맥상 의미 · 바꿔 쓰기 |
| | 표현 · 감상 | 표현상 특징 · 시어 · 시구 의미 · 인물 태도 (문학) |
| | 서술형 | 요약 쓰기 · 근거 찾아 쓰기 |

규칙
- 묶음을 여러 개 고르면 지문마다 유형을 **섞어 배분**한다. 같은 지문에서 같은 세부 유형이 두 번 나오지 않게 한다.
- 지문에 맞지 않는 유형(예: 안내문으로 순서 문제, 문학이 아닌 지문에 '표현 · 감상')은 AI가 피하고, 검토 화면에 바꾼 이유를 보인다("이 지문은 순서 유형이 어려워 대의 파악으로 바꿨어요").
- 형태가 OX면 서술형 묶음은 고를 수 없다. 서술형 묶음을 고르면 그 문항은 형태와 무관하게 서답형으로 만든다.
- **문항 수**: 기본은 "지문당 n문항"과 합계식. "총 문항 수에 맞추기"를 누르면 총수 입력 + 지문별 배분 미리보기. "지문별로 바꾸기"를 누르면 지문마다 개수를 정하는 표.
- **자세히 설정(접힘)**: 영어 선택지 언어(수능처럼 자동 / 한국어 / 영어), 직접 요청(선택, 200자).
- **항상 적용되는 규칙**(바꿀 수 없음, 설명만 보임): 원래 문항의 정답이 새 문항에 드러나지 않게 · 정답 번호 고르게 · 고른 지문 안에서만 출제.
- **[문제 만들기]** → 진행 화면: "지문 8개 중 3개 완료". 끝나면 ③으로 넘어간다.

### ③ 검토
- 맨 위 요약: "16문항 · 주의 2 · 유형 바꿈 1".
- 왼쪽: 문항 목록(번호 · 유형 · 상태 확인 필요/확인함). **주의 문항이 맨 위**. "확인 필요만 보기".
- 오른쪽 문항 카드
  - 원래 지문(정답 근거 문장 노란색), 새 문항, 정답 · 해설(서술형은 모범 답안 · 채점 기준).
  - 배지: **자동 검사 통과** 또는 **주의**(다시 풀었더니 답이 다름 · 근거 문장이 지문에 없음 · 원래 정답 노출 의심 · 유형 바꿈).
  - 동작: **고치기**(발문 · 선택지 · 정답 · 해설 바로 편집) · **다시 만들기**(같은 조건 / 한 줄 요청 추가) · **빼기** · 순서 바꾸기.

### ④ 인쇄 · 저장
- A4 미리보기: [문제지] [정답 · 해설지] 탭.
- 설정: 시험지 제목, 학원명 · 이름 칸, 1단 / 2단, 정답 위치(별지 / 문항 아래 / 빼기), 출처 표시("2026 10월 고2 학평 22번 변형").
- 정답 분포 "① 3 · ② 4 · ③ 3 · ④ 3 · ⑤ 3". 한 번호가 전체의 40%를 넘으면 [정답 위치 섞기].
- [인쇄 / PDF 저장] [저장하고 목록으로].

## 5. 시험 보관함

### 보관함 목록
- 보기 전환 **[시험지별] [지문별]**.
- 필터: 과목(내 담당 과목) · 학년 · 종류(수능 · 모의평가 · 학력평가 · 내신 · 직접 추가). 검색.
- 시험지별 표: 시험지 이름 · 과목 · 학년 · 지문 수 · 그림 지문 수 · 올린 사람 · 날짜. 내가 올린 것만 수정 · 삭제.
- 지문별 표: 번호 · 유형 · 첫 줄 · 원래 시험지 · [이 지문으로 만들기].
- 위: **[시험지 올리기]** **[지문 추가]**.

### 시험지 올리기
1. PDF 선택 + 종류 · 학년 · 시행 연월(파일 이름으로 미리 채움). 정답 · 해설 PDF는 선택.
2. 나누는 중: "지문을 나누고 있어요 (약 2분)". 다른 화면으로 나가도 계속되고 끝나면 알림.
3. **나누기 결과 확인**: 지문 목록(번호 · 유형 · 첫 줄), 표시 배지(그림 필요 · AI가 확실하지 않음). 지문을 눌러 본문 확인 · 고치기 · 합치기 · 나누기. 1차 테스트 기준 영어는 확인할 것이 거의 없고, 국어는 그림 지문과 옛글자(중세 국어)만 보면 된다.
4. [보관함에 저장] → 시험지 상세.

### 시험지 상세
- 시험지 정보 + 지문 목록. 지문마다 [이 지문으로 만들기], 위에 [이 시험지로 만들기(지문 고르기로 이동)].

## 6. 화면 모양

- 기존 리디자인의 선생님 작업공간 틀(사이드바 · 상단 바 · 표 · 버튼)을 그대로 쓴다. 값은 `design/tokens.css`, 부품 모양은 `lab/css/components.css` · `lab/css/teacher.css` 를 따른다.
- 새로 필요한 부품: 단계 표시, 칩 묶음(다중 선택), 아래 고정 요약 바, 문항 카드, A4 미리보기.
- 너비 1440 / 1024 / 390 기준으로 깨지지 않게 한다(390은 확인용 · 실제 출제는 PC 전제).

## 7. 데모 데이터

### 두 벌의 데이터
| | 아티팩트(사내 공유) | GitHub `aitest/prototype/` |
|---|---|---|
| 보관함 시험지 | 2026 10월 고2 학력평가 영어(지문 25) · 국어(묶음 15) — 1차 테스트에서 나눈 실제 데이터 | 직접 쓴 예시 지문(영어 4 · 국어 2) |
| 만들어지는 문항 | 1차 테스트 문항 32개 + 이번에 추가로 만드는 유형별 문항 | 직접 쓴 예시 문항 |
| 저장소 | 올리지 않음(`.gitignore`) | 올림 |

### '문제 만들기'를 누르면
- 1차(데모)에서는 미리 만들어 둔 **문항 풀**에서 (지문, 세부 유형)이 맞는 문항을 꺼내고, 진행 화면은 몇 초 동안 보여 준다.
- 문항 풀은 영어 10지문 · 국어 4묶음에 대해 **묶음마다 1문항 이상** 만들어 둔다(어울리지 않는 묶음 제외). 이 풀은 `aitest` 와 같은 지시문 · 같은 절차(만들기 → 정답 가리고 다시 풀기)로 만든다.
- 풀에 맞는 문항이 없으면 같은 지문의 다른 유형 문항을 쓰고, 카드에 "데모: 미리 만든 문항으로 대신 보여 줘요"를 표시한다. 풀이 없는 지문을 고르면 ① 단계에서 "데모 데이터가 있는 지문" 표시로 알려 준다.
- 주의 배지를 보여 주기 위해 1차 테스트에서 나온 실제 이슈 문항(원래 정답 노출 · 영어 선택지)을 그대로 둔다.

### 저장
- 만든 시험지 · 고친 내용은 보는 사람의 브라우저에만 저장된다(데모). 화면 구석에 "데모 · 이 브라우저에만 저장" 표시와 [데모 처음으로].

```
├─ print.css           A4 인쇄
├─ data/sample.json    GitHub 용 예시 데이터 (올림)
├─ data/real.json      아티팩트 용 실제 데이터 (올리지 않음)
└─ build.py            data 를 끼워 아티팩트용 한 묶음을 만든다
```

- 화면 코드는 `generator.js` 의 `generate(지문들, 설정) → 문항들` 한 함수만 부른다. 1차와 2차의 차이는 이 함수 안쪽뿐이다.
- 문항 데이터 모양은 `aitest/prompts.py` 의 `GEN_SCHEMA` 와 같게 둔다(유형 묶음 · 세부 유형 · 서술형 채점 기준 필드를 더한다).

## 9. 2차: 실제 AI 연결 (이번에 만들지 않음, 자리만 둠)

- 아티팩트 페이지에서 Claude 를 직접 부르는 기능으로 `generate()` 를 바꾼다. 지시문은 `aitest/prompts.py` 를 기준으로 유형 묶음 · 세부 유형 · 형태 · 난이도를 받도록 넓힌다.
- 시험지 올리기의 '나누기'도 같은 방식으로 붙인다.
- 연결 전에 확인할 것: 큰 PDF 를 넣을 수 있는지, 한 번에 여러 지문을 동시에 만들 수 있는지, 응답 시간.

## 10. 남은 확인 사항

- **서술형 · 4지 · OX 품질은 아직 테스트하지 않았다.** 7장의 문항 풀을 만들 때 함께 만들어 보고, 자동 검사와 직접 확인 결과를 `aitest/results/` 에 남긴다.
- 그림 지문을 2차에 어떻게 다룰지(선생님이 그림만 따로 붙이기 등)는 미정.
- 수학은 이 프로토타입 뒤에 따로 검토.
