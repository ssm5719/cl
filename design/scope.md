# 적용 범위

클라우드러닝은 화면 성격이 다른 곳이 세 군데다. 그래도 디자인시스템은 **하나**다. 토큰과 공통 부품을 한 벌로 두고, 화면 묶음만 각자 얹는다.

2026.10.22 에 포털과 학원 페이지를 열어 CSS 를 확인했다. 아래는 지금 코드가 실제로 그렇게 되어 있다는 기록이다(`ver=1.6.28`).

## 세 곳과 CSS

| 화면 묶음 | 주소 | 공통층 | 화면층 |
| --- | --- | --- | --- |
| 관리자 · 선생님 (작업공간) | guest.lab241.com | cl-tokens · base · components | manager.css · teacher.css |
| 학원 페이지 (공개 · 학생) | guest.lab241.com/user | cl-tokens · base · components | public.css |
| 포털 (클라우드러닝 소개) | cloudlearning.lab241.com/portal | cl-tokens · base · components | portal.css · portal-chat.css |

세 곳이 **같은 토큰 파일과 같은 공통 파일**을 그대로 쓴다. 파일 버전까지 같다. 디자인시스템 문서(이 시스템)는 이 공통층을 적은 것이다.

## 공통층 — 모두 함께 쓴다

바꾸면 세 곳이 같이 바뀐다. 한 곳만 바꾸고 싶어서 여기에 예외를 넣지 않는다.

- 색 토큰 전부. 보라 계열, 중립, 의미 색, 진도 색.
- 글자 단계와 글꼴. 작업공간 단계와 공개 화면 단계(`fs-hero` · `fs-page-title-pub` · `fs-body-public` 등)가 한 파일에 같이 있다.
- 간격 4px 단위, 컨트롤 높이, 반경, 그림자, 포커스.
- 기본 부품: 버튼, 입력 칸, 배지, 칩, 표, 메뉴, 대화상자, 토스트, 쪽 번호.
- 말투와 이름 규칙, 아이콘 한 벌.

## 화면층 — 각자 쓴다

같은 부품으로 만든 **서로 다른 화면 묶음**이다. 다른 시스템이 아니다.

| 화면 묶음 | 여기에만 있는 것 |
| --- | --- |
| 관리자 · 선생님 | 상단 바 + 사이드바 틀, 목록 화면 머리, 표 · 일괄 작업 바, 대시보드 |
| 학원 페이지 | 강의 목록 카드, 영상 시청 화면, 게시판, 로그인 · 회원가입 |
| 포털 | 소개 · 요금제, 학원 목록, 상담 신청, 큰 머리글(hero) |

화면층은 **토큰을 새로 정의하지 않는다.** 색과 크기는 `var(--cl-…)` 로 읽어 쓴다. 새 값이 필요하면 공통층에 토큰을 먼저 등록한다.

## 새 화면을 만들 때

1. 공통 부품에 있는 것으로 만든다.
2. 없으면 — 그 화면 묶음에서만 쓰나? 화면층에 둔다.
3. 두 곳 이상에서 쓰나? 공통층 부품으로 올리고 이 문서에 적는다.

같은 모양을 두 화면층에 각각 적는 순간 시스템이 갈라진다. 두 번째로 쓰는 순간이 올리는 때다.

## 학원별 대표색

학원마다 색을 바꿀 수 있게 되어 있다. `cl-tokens.css` 맨 위 네 개만 바꾼다. 세 곳이 한꺼번에 바뀐다.

`cl-primary` · `cl-primary-pressed` · `cl-primary-on-dark` · `cl-primary-tint`

예시 두 벌은 README 의 "색" 장에 있다. 네 개 밖의 색을 학원별로 바꾸지 않는다. 대비 비율이 깨진다.

## 어긋난 곳

한 벌로 쓰고 있어도 값은 벌어진다. 지금까지 확인된 것은 하나이고, 2026.10.22 에 정했다.

| 토큰 | 정한 값 | 이유 |
| --- | --- | --- |
| `cl-warning` | **#9A5200** | 흰 배경 5.86:1, 경고 배경 위 5.34:1 |

한때 #CE6E00 으로 적어 두었으나 되돌렸다. 그 값은 흰 배경에서 3.59:1 이라 글자로 쓸 수 없다. `cl-warning` 은 배지 글자 · 확인 필요 · 할 일 숫자처럼 **대부분 글자색으로 쓰이는 토큰**이라 채움용 밝은 값을 넣으면 안 된다.

값이 벌어졌을 때는 `cl-tokens.css` 한 곳만 고치면 세 곳이 함께 맞는다. 세 벌로 나누면 세 곳을 고쳐야 하고, 어느 쪽이 맞는지 알 수 없게 된다.

## 다크모드 범위

다크모드는 공통층에 있다. 그래도 **켜는 곳은 화면 묶음마다 정한다.**

| 화면 묶음 | 다크모드 | 이유 |
| --- | --- | --- |
| 관리자 · 선생님 | **쓴다** (적용됨) | 오래 보는 업무 화면. 글자와 표가 대부분이라 그대로 뒤집힌다 |
| 학원 페이지 — 로그인 후 | **쓴다** (할 일) | 밤에 강의를 본다. 영상 플레이어가 이미 검은색이라 밝은 테두리가 눈에 거슬린다. Q&A · 자유게시판 상세 · 질문 수정 포함(SQ5). 고르는 곳은 계정(프로필) 메뉴(SL3) |
| 학원 페이지 — 로그인 전(메인 · 소개) | 라이트 고정 (SL3) | 배너 · 썸네일 · 학원 로고가 올린 이미지다. 뒤집어도 이미지는 밝은 채로 남는다 |
| 포털 | **안 쓴다** | 소개 화면이고 한 번 보고 지나간다 |

학원 페이지에 넣기 전에 할 일은 두 가지다.

1. `public.css` 에 직접 적힌 색 26곳을 토큰으로 바꾼다. 이미 `var(--cl-…)` 를 451곳에서 쓰고 있어 나머지만 정리하면 된다. 관리자 · 선생님 CSS 에 한 것과 같은 작업이다.
2. 올린 이미지가 들어가는 자리(배너, 썸네일, 로고, 선생님 사진)는 뒤집지 않는다. 그 칸의 바탕만 밝은 값으로 고정한다. 어두운 화면에서 이미지만 밝게 뜨는 것보다, 이미지 칸이 밝은 판처럼 보이는 쪽이 낫다.

테마는 기기 설정(`prefers-color-scheme`)을 따르고, 로그인한 화면의 계정 메뉴 "화면 테마" 에서 바꾸면 그 브라우저에 기억한다(SL3, 2026.10.29). 로그인 전 학원 화면 · 포털은 라이트로 둔다.

학원 대표색은 어두운 배경에서 `cl-primary-on-dark` 로 바꿔 읽는다. 학원이 색을 바꿔도 이 네 번째 값까지 같이 정하면 대비가 유지된다.

## 쪼개는 때

포털이 서비스 소개용으로 완전히 다른 얼굴을 갖기로 정했을 때다. 큰 사진, 다른 서체, 움직임 중심. 그때는 포털만 따로 떼고, 색 토큰만 공유한다.

지금 포털 요금제 화면은 같은 보라, 같은 버튼, 같은 머리글 구조다. 아직 그럴 때가 아니다.

## 포털 2차 (2026.10.29)

2026.10.29 에 포털 CSS 를 다시 열어 봤다. 공통 세 파일(cl-tokens · base · components)은 1차가 반영된 새 버전을 쓴다. 그런데 `portal.css` 가 맨 위에 **포털 전용 색 변수 `--pt-*` 를 hex 로 30여 개** 따로 두고, 그라데이션 3개 · 보라빛 그림자 6개 · 자기 버튼(`cl-pt-btn`) · 자기 입력 칸 모양(높이 52 · 모서리 12)을 만든다. 같은 시스템인데 공통층을 비켜 가는 곳이다.

정한 방향(제안 — 실험실 PT 항목):

- 쪼개지 않는다. 포털도 같은 토큰 · 같은 부품을 쓴다. `--pt-*` 는 `--cl-*` 를 가리키게 했다가 지운다(PT1).
- 버튼은 공통 Button(`cl-btn`)으로. 포털의 크기 이름(`--xs` 40 · `--xl` 56)이 공통 이름과 겹쳐 값만 달랐던 문제를 없앤다(PT3).
- 포털은 처음 온 사람이 보는 소개 화면이다. 믿음을 주는 재료는 실제 학원 로고 · 실제 서비스 화면 · 출처 있는 숫자다. 3D 그림 · 그라데이션 · 유리 · 장식 숫자는 쓰지 않는다.
- 실험실 포털 화면은 사이트 CSS 사본(`lab/css/portal/`)을 쓴다. 1차 화면의 `lab/css/` 와 섞지 않으므로 포털 수정이 1차 화면에 영향을 주지 않는다.
- 테마는 라이트 고정(위 표 그대로).
